# 屏幕调通记录与调试手册

两块板的屏幕驱动是怎么点亮的、踩过什么坑、下次坏了从哪查起。
烧录与备份操作见 [HARDWARE.md](HARDWARE.md)，线上协议见 [protocol.md](protocol.md)。

定位说明：现有固件是 bring-up 基线（已点亮、已验证），固件主体后续整体重写。
重写换的是架构，下面这些硬件事实和排查方法照旧有效——尤其是第 2 节定下的等 BUSY 纪律。

## 1. 现状

| 项目 | ZKC21V（2.1） | ZKC42V（4.2） |
|---|---|---|
| 显示 | 已调通 | 已调通 |
| 方向 | host 内置补偿：rotate 90 + mirror-y（只对 128×250 生效） | 原生横屏，零补偿 |
| BLE 传图 | 已验证：MTU 247，8,000 B，分块/CRC/COMMIT 全过 | 已验证：30,000 B，协议与 2.1 相同（format 2 双平面） |
| 刷屏 | `--clear` / `--test` / `--image` 均正常 | 同左，全刷最长 30 s |
| RGB LED | 状态机已实现，灯语见 [HARDWARE.md](HARDWARE.md)；整套灯效未逐项实测 | 板上无 LED |
| 驱动文件 | `src/epd_ssd1680.c` | `src/epd_jd79668.c` |

两板都未实现：OTA、低功耗（默认不睡，`PM=1` 选配）、局部刷新、图片落盘、按键/NFC/电池电压、GUI。
OEM SecureBoot/EFUSE 状态未验证——不过 2.1 已实际启动过自制固件，protected/MBR/工厂区从未被写过。

## 2. 2.1 花屏结案报告

**症状**（修复前）：BLE 全链路（INFO/BEGIN/DATA/CRC/COMMIT）应答正常，`--clear`、`--test`
都能触发刷屏动作，但屏上黑白红三色搅成一团噪点——不是预期的白屏，也不是测试卡。
宿主侧能怀疑的都排除了：连接、传输长度、CRC、COMMIT 执行。问题锁定在 EPD 时序。

**根因**：`0x20`（主激活）发出后固件没有等 BUSY 就继续写 RAM。面板还在忙，这批写入被静默丢弃。
修复是完整初始化序列 + 每步 `0x20` 之后轮询 BUSY 到空闲（`epd_ssd1680.c` 的现状），一次改对。

由此定下项目纪律（已写进 README 贡献指南）：**任何 `0x20` 激活之后，必须等 BUSY 空闲才能发
下一条命令，没有例外。**

另一条经验随结案一并存档：结案之前，`epd_ssd1680.c` 里的初始化/刷新参数只是 bring-up 猜测值，
不构成结论——当时围绕参数做的多轮尝试全部无效。现在驱动是实机验证过的；但换玻璃、换批次，
仍按第 4 节流程重新核对。

## 3. 4.2 点亮：JD79668AA

第一版驱动按 UC8276 指令集写，结果是屏被送进睡死。实测认定控制器是 JD79668AA——
SSD1680 兼容指令集，但细节参数与 2.1 的 SSD1680 不通用。改写为 `epd_jd79668.c` 后一次点亮。
两个最容易踩的差别都实测过：

- 边框波形 `0x3C` 用 `0x01`（2.1 用 `0x05`）；
- 数据方向 `0x11` 用 `0x03`（X/Y 双向递增；2.1 用 `0x01`）。

完整序列（全部实机验证）：

```text
初始化  0x12 软复位 + 等BUSY
        0x01 (h-1, 3 字节)
        0x3C 0x01                                        边框
        0x18 0x80
        0x11 0x03                                        数据方向
        0x44 00 31 / 0x45 0000 2B01 / 0x4E 00 / 0x4F 00   窗口与计数器
        0x22 0xB9 + 0x20 + 等BUSY
显示    0x24 黑平面（原生序）/ 0x26 红平面（取反）
        0x21 00 40
        0x22 0xF7 + 0x20 + 等BUSY（全刷最长 30 s）
        0x10 0x01                                        深睡
```

方向：原生横屏 400×300。host 的 2.1 自动补偿只对 128×250 生效，4.2 不带 rotate/mirror 直接发。

## 4. 排查手册（换屏 / 再花屏）

先做一个判断再谈驱动：`--preview out.png` 存一张量化结果。预览对而屏错，是驱动/时序问题，
往下走；预览本身就错，是 host 侧问题（阈值/旋转/镜像/裁剪），别冤枉屏。

排查顺序按可靠性从高到低：

1. **确认屏的实物身份。** 拆开看 FPC 丝印，主板正反面与排线拍照。"2.13 寸 BWR" 不是身份——
   同尺寸的屏，不同玻璃/批次可以用不同 LUT、VCOM、border。
2. **找这个型号/批次的厂商初始化序列。** 控制器兼容不等于参数通用。
3. **逻辑分析仪抓一次已知良好工作的 SPI。** SCK/MOSI/CS/DC/RST/BUSY 全接，录上电初始化 +
   一次清屏 + 一次图片刷新。2.1 的 BUSY 问题、4.2 的睡死，最终都是靠"和能工作的行为对比"
   定的案——这是唯一不依赖猜想的证据。
4. **最小化验证。** 只做清屏，目标整屏纯白。清屏不正常，不要去调图片数据。
5. **平面分离。** 全白、全黑、全红分开发送，看坏的是哪一层。
6. **逐条核对指令。** `0x11` 数据方向、`0x44/0x45` 窗口、`0x4E/0x4F` 计数器、`0x22` 刷新序列、
   `0x3C` 边框，以实屏 datasheet 或厂商 demo 为准。
7. **交叉对比。** 还不行就换一块已知良好的同控制器参考屏，或对出厂固件抓 SPI 对照。

当初排查时留下的未确认清单，再遇花屏时逐项过：

- 控制器实物型号
- FPC 型号/批次
- 初始化、窗口、数据方向、刷新序列与这块玻璃的匹配度
- BUSY 极性与等待时序
- 本批次的 LUT / VCOM / border
- 位序与平面顺序和控制器 RAM 约定的一致性

## 5. PM 睡眠事故（2026-11-06，已结案）

**现象**：BLE 端 COMMIT/CLEAR 应答正常，`0xE2`（DONE）永远不来，屏一动不动。

**定位**：卡死现场用 `probe_21v.bat` attach——PC 停在 `drv_spi_transfer+0x104`，TX-FIFO 轮询里。
CPU 在转，SPI 外设已经停了。与上一版正常固件（golden）做 A/B，唯一差异是"主循环开 PM 睡眠"。
机理：刷屏进行中，BLE 事件触发 light-sleep，高速时钟被切走，正在飞行中的同步 SPI 事务断粮，
`drv_spi_transfer` 死等一个永远不会动的 FIFO。

**处置**：

- PM 降级为选配：`make PM=1`（宏 `PM_SLEEP_ENABLE`），默认构建不睡系统，行为与 golden 一致。
- 正解方向已实现到 PM 候选构建（`*_pmtest`）：刷屏期间 `pm_sleep_prevent(PM_ID_USER0)` 守护、
  结束后 allow（`ble_epd_task` 内，包住 `epd_show`/`epd_clear`）。重新启用 PM 前先台架复测。
- 板级附带结论：EPD EN 必须在 `board_init()` 就拉高，运行中途再开电源的浪涌同样能拖垮总线。

**Makefile 教训**（单独记）：`DEFINES +=` 必须写在 `DEFINES =` 之后，否则整行被覆盖，
宏根本没编进去。这条是踩出来的：做 A/B 实验前，先 `cmp` 两个 bin 确认真的不同，再谈结论。

**调试尾巴**：`make EPDDBG=1` 的构建在 DONE 通知里多带 12 字节（init/refresh 的等 BUSY
超时位图、耗时、BUSY 电平、SPI 错误计数）。代码常驻源码树，野外再炸可以直接开。

## 6. 功耗

实测（ZKC21V，台架电源 3.3 V，2026-11-06）：

| 状态 | 电流 |
|---|---|
| 空闲广播（100 ms 间隔） | 3.0 mA |
| BLE 传图 | 3.0 mA |
| 刷屏窗口 | 平均 9.0 mA（峰值 0.3 A） |

读数解读：4.2 没有灯，空闲同为 3 mA——灯不是大头，CPU 不睡才是。由此动过两处：

1. 主循环补上 `pm_sleep_enable(true)` + `pm_power_manage()`（原厂 ble_app_simple 的姿势）。
   这正是第 5 节事故的起点，后来降级为 `PM=1` 选配。
2. 面板 EN 的断电策略与首次上电时机（现状见 [HARDWARE.md](HARDWARE.md) 第 2 节）。

预期：PM 启用且灯熄时，空闲应低于 1 mA（只剩 100 ms legacy 广播）。
2.13 若开蓝灯心跳，广播态平均再加 1–2 mA——默认已改为广播时全灭（`LED_IDLE_BLINK=0`）。

电池账（18650 3,000 mAh，按可用 85%、LDO 电流 1:1 估算）：

| 固件形态 | 平均电流 | 续航 |
|---|---|---|
| 现状默认（不睡） | ~3 mA | ~1 个月 |
| 灯灭 + 广播间隔 3–5 s | 0.5–1 mA | 4–8 个月 |
| 深睡 duty cycle（重写后的目标形态） | ~0.1 mA | >1 年（受自放电限制） |

刷屏能量可忽略：9 mA × 20 s ≈ 0.05 mAh/张。
